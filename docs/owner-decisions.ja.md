## 書き方

- 選ぶものの `[ ]` を `[x]` にします。
- 「暫定案」は、設計書に今書いてある案です。暫定案のままでよければ、暫定案に `[x]` を付けるだけで構いません。
- まだ決められない項目は「保留」に `[x]` を付けます。理由や、決めるために知りたいことがあれば「メモ」に書いてください。
- 「メモ」には、条件、理由、Claude への質問など、何を書いても構いません。
- 全部の項目を一度に埋める必要はありません。埋めたところまでで渡してください。

## D-08 パッケージサイズの上限

期限: 段階1 の前。

メモ:

パッケージサイズの上限を、よく 10MB と見かけるが、これは何か根拠があるのか？
10MB を超えるとエラーになる等の重要な制約があるならば、それに従う。
もしも配布データ量や起動時間の観点の問題ならば、実装実現を優先して、10MB という数字は緩和したい。

## D-13 印刷の問題を Joplin に報告するか（設計書 0.4 で追加）

期限: 急がない（v1.0 の公開の前までに）。

Joplin のデスクトップ版は、印刷のときにプラグインの Markdown-it のコンテンツスクリプトを読み込まないため、印刷では ECharts の図が出ません（PDF のエクスポートでは出ます）。原因は `packages/app-desktop/gui/WindowCommandsAndDialogs/utils/usePrintToCallback.ts` で、印刷の呼び出しだけが `plugins` を渡していないことです。

- [ ] Joplin に issue を出す
- [ ] Joplin に修正の PR を出す（`plugins: props.plugins` を1行加える見込み）
- [x] 出さない。README で「PDF にエクスポートしてから印刷する」と案内するだけにする（暫定案）
- [ ] 保留

issue や PR は Joplin の公開のリポジトリへの投稿になるので、出す場合は作者のアカウントで、作者の指示で行います。Claude は文面の案を作れます。
