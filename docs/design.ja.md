## 1. 概要

### 1.1 目的

Joplin のノート（Markdown）に書かれた ECharts のコードブロックを、Joplin 本体のノートビューア上で図（SVG）として表示するプラグインを提供する。

Joplin 本体は Mermaid をサポートしており、` ```mermaid ` と書くだけで図が表示される。本プラグインは **「インストールするだけで、Mermaid と同等の使い勝手で Apache ECharts のグラフが使える」** ことを目標とする。ECharts は、Mermaid の `xychart` や `pie` よりはるかに多くの種類のグラフ（散布図、レーダー、ヒートマップ、ツリーマップ、サンキー、ローソク足、箱ひげなど）を描ける。

### 1.2 設計方針

1. **ゼロ設定で動く**: インストール直後から、追加のソフトウェアや設定なしで描画できる。
2. **オフライン・外部通信なし**: ECharts を同梱してローカルで実行する。本プラグインはネットワーク通信を一切行わず、ノートの内容を外部に送らない。Joplin のノートビューアの CSP は外部の画像を止めない（4.1節）ので、外部の URL はプラグインが取り除く（12章）。これを主なアピールポイントとして、公開する場で明記する（21.7節）。
3. **Joplin の流儀に従う**: Markdown-it コンテンツスクリプト、`joplin-editable` 構造、設定 API、テーマなど、Joplin 本体および Mermaid 実装と同じ仕組み・見た目に揃える。
4. **最初から国際化**: UI 文字列はすべて gettext と PO ファイルで管理する。
5. **テーマは Joplin に合わせる**: 図の配色（Light / Dark）は、既定では Joplin のテーマの明暗に自動で合わせる。設定画面で固定することもできる。
6. **MIT ライセンスで、エンジンを内蔵して配布する**: 本プラグインは MIT ライセンスとし、ECharts（Apache-2.0）をプラグインに内蔵して配布する（20章）。
7. **公開を前提に作る**: リリースできる品質になったら、GitHub で公開し、GitHub Releases と npm でリリースして、Joplin 公式プラグイン一覧に掲載する（21章。作者の方針: リリースできそうなら公開する）。
8. **生成 AI の利用を明記する**: 本プラグインは生成 AI（Anthropic の Claude）を全面的に用いて開発する。作者が出力を確認して管理していることと合わせて、README などに明記する（22章）。

### 1.3 スコープ

| 区分         | 内容                                                                                                                                                                                                                                                                                                                                                                            |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 対象（v1.0） | ノートビューアでの静的なグラフ（SVG）の描画、エクスポート（PDF、HTML）での描画（D-04。印刷は Joplin の問題で図が出ないため、PDF のエクスポートで代わりにする。14章）、入力の形式（JSON と YAML）、Light / Dark（Joplin のテーマに自動で追従。設定で固定も可）、図の文字サイズの扱い、Markdown エディタでの JSON / YAML の構文ハイライト、設定画面、i18n、エラー表示、図のコピー・保存、デスクトップ版（Windows / macOS / Linux）、GitHub での公開、npm への公開、Joplin 公式プラグイン一覧への掲載 |

## 4. 前提となる技術要素

### 4.1 Joplin プラグインの仕組み

本プラグインで使う Joplin プラグイン API は、基準プラグイン（4.1節）と同じ。

| API                                                                              | 用途                                                                           |
| -------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| `joplin.contentScripts.register(ContentScriptType.MarkdownItPlugin, id, path)`   | Markdown-it プラグインとアセットの登録                                         |
| `joplin.contentScripts.register(ContentScriptType.CodeMirrorPlugin, id, path)`   | Markdown エディタへの構文ハイライト拡張の登録                                  |
| Markdown-it プラグインの `options.settingValue(key)`                             | 描画のときにプラグインの設定値を読む（9章）                                    |
| Markdown-it プラグインの `options.theme.appearance`                              | Joplin のテーマの明暗（8.2節）                                                 |
| `joplin.contentScripts.onMessage(id, handler)`                                   | ビューアスクリプトからの依頼（コピーと保存、ツールバーの翻訳）に応答する       |
| `webviewApi.postMessage(id, message)`（ビューア側）                              | メインスクリプトへの依頼                                                       |
| `joplin.settings.registerSection` / `registerSettings` / `value` / `globalValue` | 設定画面、設定値、Joplin のロケール                                            |
| `joplin.clipboard`、`joplin.views.dialogs`、`joplin.require('fs-extra')`         | 図のコピーと保存（11章）                                                       |
| ビューアのイベント `joplin-noteDidUpdate`                                        | ノート本文の再描画後に、ツールバーを付ける合図                                 |

最低対応バージョン（`app_min_version`）は **Joplin 3.1** とする（基準プラグインと同じ根拠。動作確認は最新の安定版で行う）。

**ノートビューアの CSP**（試作の段階C で、Joplin 3.7.24 で実測）:

```text
default-src 'self' ; img-src 'self' blob: data: * ; media-src 'self' blob: data: * ;
child-src https://*.youtube.com https://*.youtube-nocookie.com ; object-src 'none' ;
form-action 'none' ; style-src 'self' 'unsafe-inline' * data:
```

- `eval`、`new Function`、WebAssembly は使えない。Web Worker は作れない（基準の教訓 1.1節）。
- **`img-src` と `style-src` に `*` があり、外部の画像は CSP では止まらない**。外部の画像を止めるのはプラグインの役目になる（12章）。
- `style-src` に `'unsafe-inline'` があり、SVG の `style` 属性と `<style>` 要素は効く。
- ページは `about:`、プラグインのファイルは `file:` の URL で読み込まれる。

**Markdown-it のコンテンツスクリプトが動く環境**（試作の2回目で、Joplin 3.7.24 で確認。基準の教訓にはない）:

- デスクトップ版では、Electron の renderer プロセスで動く。Joplin は Node の `require` で読み込む（`packages/lib/services/plugins/utils/loadContentScripts.ts` の `shim.requireDynamic`）。`window`、`document`、画面に出さない Canvas、DOMPurify が使える。
- Markdown-it の規則は同期的に HTML の文字列を返す。Promise は待たない。描画にかかった時間だけ、ノートの表示全体が待たされる。
- Joplin が渡す options は場面で違う。ノートビューアとリッチテキストエディタには `whiteBackgroundNoteRendering` があり、エクスポート（PDF、HTML）には代わりに `plainResourceRendering` がある。エクスポートでは `theme.appearance` が常に `light` になる。
- エクスポートでは、アセット（JS と CSS）がファイルとして参照されず、HTML の中に直接書き込まれる。アセットの JS が自分の URL から追加のファイルを探す方法は使えない（教訓 1.1節）。
- 印刷では、Joplin の問題で、プラグインの Markdown-it のコンテンツスクリプトが動かない（教訓 1.4節。14章）。

### 4.2 Apache ECharts

**採用**: Apache ECharts **6.1.0**（2026-05-19 公開、Apache-2.0）。作者が試作の結果を受けて決定した（2026-11-23）。以後の更新は 19章 D-07 の方針による。6.1.0 未満には XSS の脆弱性（GHSA-fgmj-fm8m-jvvx）があるため、6.1.0 未満には戻さない。

**選んだ理由**（エンジンの選定は作者の非公開の作業用リポジトリで行った。要点だけを書く）: 必須の条件（ブラウザだけで動く、WASM・Worker・動的なコード生成を使わない、外部通信を止められる、ライセンス）をすべて満たし、SVG を文字列で作る API があり、Dark のテーマと多くの言語のロケールを内蔵し、Apache 財団のプロジェクトで保守が安定している。

**使い方の要点**:

| 項目       | 内容                                                                                                                                                                                                                                                 |
| ---------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 描き方     | `echarts.init(null, テーマ, { renderer: 'svg', ssr: true, width, height, locale })` で描画先のないインスタンスを作り、`setOption(option)` のあと `renderToSVGString()` で SVG の文字列を得て、`dispose()` する。DOM を使わないので、表示前でも描ける |
| 同梱する版 | 公式の圧縮版をそのまま同梱する（D-09。15.1節）。描画の方式の変更（0.4）に合わせて、ES モジュールの `dist/echarts.esm.min.mjs` から、UMD の `dist/echarts.min.js`（1,121,883 バイト）に変える。コンテンツスクリプトが実行時に `require` で読む（V-13）。取得元のファイルと同じであることを SHA-256 で確かめる |
| テーマ     | `default`（明るい）と `dark` が本体に入っている                                                                                                                                                                                                      |
| ロケール   | 本体には英語と中国語だけ。ほかの言語は `lib/i18n/langXX.js` を登録して使う（10.3節）                                                                                                                                                                 |
| 文字の幅   | 画面に出さない Canvas の `measureText` で測る。日本語なども正しく測れた                                                                                                                                                                              |

**試作の結果の要約**（詳細は `docs/spike-results.ja.md`。試作のコードは `spike/engine`、`spike/plugin` ブランチにある）:

| 段階                     | 主な結果                                                                                                                                                                                                   |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A（調査）                | ライセンスは Apache-2.0。d3.js の一部（BSD-3-Clause）を取り込んでいる。Worker、WASM、通信の API はない。動的なコード生成は地図の古い経路の1か所だけで、描画では通らない。ES モジュールの形は全部入りだけ   |
| B（ヘッドレスの Chrome） | 20 種類の図がすべて描けた。日本語・中国語・韓国語ははみ出さない。読み込み 100〜125ms、2回目以降の描画 1〜13ms。グローバル変数を作らず、ページに要素を足さない。悪意のある文字は SVG の中でただの文字になる |
| C（Joplin 3.7.24）       | Markdown のビューアとリッチテキストエディタで描けた。ソースの往復と編集画面も問題なし。テーマの切り替えに追従した。SVG の `style` 属性と `<style>` 要素が効いた                                            |
| C の2回目（Joplin 3.7.24） | ビューアスクリプトで描く方式では PDF のエクスポートで図が出なかった。Markdown-it のコンテンツスクリプトで SVG を作る方式にすると、ノートビューア、暗いテーマ、PDF と HTML のエクスポート、リッチテキストエディタで図が出た。印刷は Joplin の問題で出ない。図1つ 15ms |

## 5. アーキテクチャ

### 5.1 構成

**描画は Markdown-it のコンテンツスクリプトの中で行う**（0.4 で変更）。Markdown を HTML にするときに、ECharts で SVG の文字列を作って無害化し、HTML に直接入れる。基準プラグインはビューアスクリプトで描くが、その方式ではエクスポート（PDF、HTML）で図が出ないため、本プラグインでは採らない（試作の2回目。教訓 1.1節）。

この方式の利点と注意点:

- 利点: ノートビューア、リッチテキストエディタ、PDF と HTML のエクスポートが、同じ仕組みで図を出す。HTML のエクスポートの出力は SVG を含むだけで、エンジンのファイルもスクリプトも要らない。図の表示のためにビューアとメインスクリプトの間でやり取りをしない。
- 注意点: 描画は同期的に行う。描いている間、Joplin のノートの表示全体が待たされる（7.3節、13章）。描く幅はペインの幅を知らずに決める（8.7節、D-12）。

ビューアスクリプトは、図のツールバー（コピー、保存。11章）だけを担当する。図が描けるかどうかには関わらない。

```text
Markdown エディタ ─(ノート本文)→ Markdown レンダラー ─(fence)→ Markdown-it コンテンツスクリプト
                                                                  │ option → 入力の検査 → ECharts エンジン
                                                                  │   → SVG の文字列 → 無害化（キャッシュ: LRU）
                                                                  ▼
                       HTML（SVG を含む）→ ノートビューア / リッチテキストエディタ / エクスポート（PDF、HTML）
                                              │
                         ビューアスクリプト（ツールバーだけ）─ postMessage ─→ メインスクリプト（コピー・保存）
Markdown エディタ ← CodeMirror コンテンツスクリプト（JSON / YAML の色分け）
```

### 5.2 描画シーケンス

1. 利用者がノートを開く・編集する（またはエクスポートする）。Joplin のレンダラーが Markdown-it プラグインを呼ぶ。
2. Markdown-it プラグインが ` ```echarts ` のブロックを見つけ、設定値（`options.settingValue`）と `appearance` から、有効テーマ、描く幅と高さ、文字サイズ、ロケールを決める。
3. キャッシュキーを計算し、キャッシュがあれば、その HTML を使う。
4. なければ、入力を解析し（JSON / YAML）、入力の検査とプラグインの検査をして、エンジンで描き、無害化する。結果（SVG、注意、ECharts のメッセージ）をキャッシュに保存する。
5. Joplin の本体のコードブロックと同じ形の HTML に、SVG と注意を入れて返す（7.1節）。
6. ノートビューアでは、Joplin が本文を差し替えて `joplin-noteDidUpdate` を送る。ビューアスクリプトが、図にツールバーを付ける。

## 6. 記法の仕様

### 6.1 対象とするコードブロック

````markdown
```echarts
{
  "xAxis": { "type": "category", "data": ["Mon", "Tue", "Wed"] },
  "yAxis": {},
  "series": [{ "type": "bar", "data": [120, 200, 150] }]
}
```
````

| 項目                       | 仕様                                                                                                                                           |
| -------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| 言語名 | `echarts`（大文字・小文字は区別しない）。設定で別名を追加できる。`json` は既定では受け付けない（ふつうの JSON のコードブロックと区別できず、関係のない JSON までグラフとして描こうとしてしまうため。D-01）。利用者が設定で `json` を足すことはできる |
| 中身 | ECharts の `option`。JSON または YAML で書く（D-02。6.3節） |
| 1ブロック内の図            | 1つ                                                                                                                                            |
| フェンスの長さ、インデント | 基準プラグインと同じ（3文字以上、閉じフェンスは同じ文字で同じ長さ以上。リッチテキストエディタの編集画面で OK を押すと3文字に組み立て直される） |

### 6.2 ブロック単位のオプション

| オプション | 値                          | 説明                                                                                                             |
| ---------- | --------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| `theme`    | `light` / `dark` / `none`   | このブロックだけテーマを指定する。`none` は ECharts の既定のテーマで描き、プラグインは背景も文字サイズも変えない |
| `align`    | `left` / `center` / `right` | 図の配置（既定は `center`）                                                                                      |
| `height`   | 数（px）                    | 図の高さ。ECharts は高さを入力から決めないため。既定は設定の値（400）。範囲は 100〜2000                   |
| `width`    | 数（px）                    | 図を描く幅。既定は設定の値（800）。範囲は 200〜4000（8.7節。D-12 で追加）                                         |

`theme`、`align`、`height` の3つは D-03 で、`width` は D-12 で入れると決めた。不明なオプションは無視する。

### 6.3 入力の形式

- **JSON**: 中身の最初の空白でない文字が `{` なら JSON として解析する（`JSON.parse`）。構文の誤りは、例外のメッセージの位置から行番号を出す。
- **YAML**: それ以外は YAML として解析する（`yaml` パッケージ。ISC）。コメントが書け、引用符をほとんど省けるので、手で書きやすい。YAML の別名（`*name`）の展開には上限を設け（`maxAliasCount`）、巨大な展開を防ぐ。構文の誤りは、パーサーが返す行番号を出す。
- 解析した結果は、オブジェクト（`{}`）でなければエラーにする。
- **関数は書けない**: 入力を JavaScript として評価しない。`formatter` の関数などは使えない（文字列のテンプレート `'{b}: {c}'` は使える）。README の「制限事項」に書く。

YAML の例:

````markdown
```echarts
# 月別の売上
xAxis: { type: category, data: [1月, 2月, 3月] }
yAxis: {}
series:
  - type: bar
    data: [120, 200, 150]
```
````

## 7. 描画処理の詳細

### 7.1 Markdown-it プラグインの出力

基準プラグイン（7.1節）と同じ `joplin-editable` の形にし、図の出力の要素の中に SVG を直接入れる（試作の1回目と2回目で、リッチテキストエディタとの往復と編集画面で問題がないことを確認した）。

```html
<div class="joplin-editable joplin-echarts" data-echarts-theme="{有効テーマ}">
  <pre class="joplin-source"
       data-joplin-language="{info 文字列}"
       data-joplin-source-open="{開きフェンス}{info 文字列}&#10;"
       data-joplin-source-close="&#10;{閉じフェンス}">{エスケープ済みソース（末尾の改行を1つ除く）}</pre>
  <div class="joplin-echarts-output" role="figure" aria-label="{図の名前}">{無害化した SVG、またはエラーボックス}</div>
  <div class="joplin-echarts-notes">{注意（あれば）}</div>
</div>
```

- 末尾の改行を1つ除き、閉じフェンスを改行から始める。`data-joplin-language` に info 文字列全体を入れる（基準の教訓 1.4節）。
- アセットとして宣言するのは `viewer.js`（ツールバーだけ）と CSS だけ。エンジンのファイルは宣言しない（基準の教訓 1.3節）。
- 図の表示はアセットの JS に頼らない。エクスポートでアセットが HTML に書き込まれても、書き込まれなくても、図は出る。

### 7.2 描画の処理の流れ（Markdown-it プラグイン）

- fence の規則の中で、ブロックごとに同期的に描く（5.2節）。
- キャッシュキーは `hash(ソース + 有効テーマ + 描く幅 + 高さ + 基本文字サイズ + 最小の文字サイズ + 背景の設定 + ロケール + エンジン版数 + プラグイン版数)`。キャッシュは、コンテンツスクリプトのモジュールの中に持つ（renderer プロセスの中で、ノートをまたいで共有される）。
- **描く幅**: 設定の幅、またはブロックの `width=`（8.7節。D-12）。Markdown-it の段階ではペインの幅が分からないので、幅の変化に合わせて描き直すことはしない。
- 描画の結果（SVG、注意、ECharts のメッセージ）をまとめてキャッシュに入れる（7.4節）。
- 設定は描画のたびに `settingValue` で読む。設定を変えたときに Joplin がノートを描き直すかは段階1 で確かめる（V-10）。描き直さない場合は、ノートを開き直すと反映されることを設定画面の説明に書く。

### 7.3 編集中の再描画

- Joplin は、編集のたびに（Joplin のデバウンスの後で）ノート全体を描き直す。図の描画は同期的なので、描いている間は表示全体が待たされる。
- 変更のないブロックはキャッシュから出すので、ECharts は呼ばれない。ECharts の描画は1図あたり数 ms〜数十 ms（試作の2回目で 15ms）なので、ふつうの図では体感できない見込み。
- 大きな図（試作では、1万切れの円グラフで 1.8 秒）を書き換えていると、入力のたびに待たされる。最大文字数（9章）で上限を決め、段階1 で編集中の体感を確かめる（V-14）。
- 基準プラグインの「直前の図を残す」「直列キュー」「タイムアウトの表示」は、非同期の描画のための仕組みなので作らない。描画は止められないので、タイムアウトはない。

### 7.4 エラー表示

| 場合                                                  | 表示                                                                   |
| ----------------------------------------------------- | ---------------------------------------------------------------------- |
| JSON / YAML の構文の誤り                              | エラーボックスに、メッセージと行番号と該当行の抜粋（色分けつき）を出す |
| 中身がオブジェクトでない、大きさの上限を超えた        | エラーボックス                                                         |
| 地図（`geo`、`series.type: 'map'`）を使っている       | エラーボックス（「地図は使えない」）。エンジンに渡す前に検出する       |
| プラグインの検査で見つかった誤り（下の表） | エラーボックス、または図の下の注意 |
| エンジンの例外 | エラーボックスに ECharts のメッセージを出す（行番号はない。公式の圧縮版では `Cannot read properties of undefined` のような分かりにくい文になることがあるので、「ECharts が描けませんでした」と添える） |
| エンジンの警告 | 図の下に注意として出す。図は描く |
| 描けるものがない（`series` がない、すべて未知の種類） | 空の図ではなく、「描くものがありません」と注意を出す                   |
| 入力の検査で、見た目が変わる項目を取り除いた          | 図の下に注意（「外部の画像は表示しません」など）                       |

- **プラグインの検査**（D-09 で公式の圧縮版を使うため。`src/contentScript/optionCheck.ts`）: 公式の圧縮版は開発用の検査を省いているので、試作の段階B で確かめた、よくある誤りをプラグインが検査する。

  | 誤り | 公式の圧縮版の結果 | プラグインの表示 |
  | --- | --- | --- |
  | 存在しない `series.type` | 警告もなく空の図 | 注意「未知のグラフの種類: nosuchchart」。種類の一覧は ECharts 6.1.0 の配布ファイルから作り、版を更新したら作り直す |
  | `series.data` が配列でもオブジェクトでもない | 警告もなく空の図 | 注意「`series[0].data` は配列にしてください」 |
  | 直交座標の系列（`bar`、`line`、`scatter` など）なのに `xAxis` か `yAxis` がない | 意味の分かりにくい例外 | エラー「棒グラフなどには `xAxis` と `yAxis` が必要です」 |
  | `series` がない、空 | 背景だけの空の図 | 注意「描くものがありません」 |

  検査で見つからない誤りは、エンジンの例外または空の図になる。検査の範囲は段階1 で決め、テストで固定する（V-09）。
- エンジンの警告は、描画の間だけ `console.warn` と `console.error` を受け取って集める。ECharts は一部のメッセージをページの中で1回しか出さないので、描画の結果のキャッシュにメッセージも入れ、描き直しても表示する（試作の段階C で発見）。
- ECharts のメッセージは英語のまま表示する。
- エンジンから来た文字と、入力の抜粋は、HTML としてエスケープしてから HTML の文字列に入れる。
- 編集中にエラーになったときに直前の図を残す仕組み（基準プラグイン）は作らない（7.3節）。Markdown-it の段階では、編集の前後でどのブロックが同じかを確実には決められないため。
- エラーボックスと注意は、エクスポート（PDF、HTML）にもそのまま出る。

### 7.5 エンジンの読み込みと呼び出し

- 最初の ECharts のブロックを見つけたときに、同梱した公式の UMD の圧縮版（`engine/echarts.min.js`）を、Node の `require` で読み込む（遅延読み込み。webpack にまとめさせないよう `__non_webpack_require__` を使い、場所はコンテンツスクリプトのファイルの場所から求める。15.1節、V-13）。ロケールのファイルも、必要な1つだけを読んで `registerLocale` する。
- ECharts のブロックのないノートでは、エンジンを読み込まない。
- renderer プロセスで同期的に動かす（Worker は使わない）。
- 呼び出しのたびに、`init`、`setOption`、`renderToSVGString`、`dispose` を行う。インスタンスは使い回さない。
- **同じ入力から同じ図にする**: 描画の間だけ `Math.random` を固定の種の乱数（mulberry32 など）に置き換え、`finally` で必ず元に戻す。`series` のうち `type: 'graph'` かつ `layout: 'force'` のものには `force.layoutAnimation: false` を設定する。
- アニメーションは無効にする（`animation: false`）。

### 7.6 エンジン抽象化インターフェース

開発の指示文書の共通の形（`RenderEngine`）を使う。ただし、Markdown-it の規則の中で呼ぶので、`init` と `render` を同期の関数にし、`timeoutMs` を除いた（0.4 で変更。開発の指示文書に、同期の形もあってよいことを報告する）。

```ts
interface RenderEngine {
  readonly name: string;      // "echarts"
  readonly version: string;   // "6.1.0"。キャッシュキーに含める
  readonly output: 'svg';
  init(): void;
  render(option: object, opts: RenderOptions): RenderResult;
}

interface RenderOptions {
  theme: 'light' | 'dark' | 'none';
  background: string | null;   // SVG の中に塗る背景。null は塗らない（8.5節）
  width: number;
  height: number;
  baseFontSize: number | null; // null はエンジンの既定（12px）
  locale: string;              // ECharts のロケール（"JA" など）
}

type RenderResult =
  | { ok: true; output: string; warnings: string[] }
  | { ok: false; reason: RenderFailure; message: string; line?: number };

type RenderFailure = 'syntax' | 'invalid' | 'blocked' | 'crash' | 'engine';
```

- 入力の解析（`syntax`）と入力の検査は、エンジンを呼ぶ前に `markdownItPlugin.ts` が行う。`blocked` は地図など、禁止した機能を使っている場合。
- `warnings` には、ECharts の警告と、入力の検査で取り除いた項目のうち注意を出すものを入れる。

### 7.7 Markdown エディタでの構文ハイライト

基準プラグイン（7.7節）の仕組み（`ViewPlugin` と `Decoration.mark`、エディターのテーマの色、見えている範囲だけ）を使い、字句解析を JSON / YAML 用にする。

| 種類             | 例                          | ハイライトタグ  |
| ---------------- | --------------------------- | --------------- |
| キー             | `"series"`、`xAxis:`        | `propertyName`  |
| 文字列           | `"bar"`                     | `string`        |
| 数値             | `120`、`-1.5e3`             | `number`        |
| 真偽値・null     | `true`、`null`              | `bool` / `null` |
| コメント（YAML） | `# 月別`                    | `comment`       |
| 記号             | `{` `}` `[` `]` `:` `,` `-` | 色分けしない    |

ECharts に固有の語（`series` の種類の名前など）は色分けしない。

## 8. テーマとスタイル

### 8.1 ECharts 側のスタイル手段

| 手段                 | 例                        | 本プラグインでの使い方                                    |
| -------------------- | ------------------------- | --------------------------------------------------------- |
| テーマ               | `init(null, 'dark')`      | 有効テーマが Dark のとき `dark`、Light のとき既定のテーマ |
| `backgroundColor`    | `'transparent'`           | 背景の扱い（8.5節）                                       |
| `textStyle.fontSize` | `14`                      | 基本の文字サイズ（8.7節）                                 |
| 利用者の `option`    | `color`、`itemStyle` など | プラグインは変えない。利用者の指定が優先される            |

### 8.2 テーマモード

基準プラグインと同じく、設定 `themeMode` で Auto（既定）/ Light / Dark を選ぶ。Auto は、Joplin が Markdown-it のプラグインに渡す `appearance` で明暗を決める（0.4 で変更。試作の2回目で、Joplin のテーマを切り替えると `appearance` が変わり、図が描き直されることを確かめた。Mermaid の図とも配色がそろう）。基準プラグインの、背景色の相対輝度で判定する方法は使わない（ビューアスクリプトで描かないため）。

**エクスポート（PDF、HTML）では `appearance` が常に `light` になる**ので、Auto の図は明るい配色で書き出される。設定 `themeMode` を Dark にした場合は、エクスポートでも Dark の図になる（背景を SVG の中に塗るので読める。8.5節）。

### 8.3 有効テーマの決定

1. ブロックに `theme=` の指定があれば、それを使う。
2. なければ、設定 `themeMode` が Light / Dark ならその値を使う。
3. Auto なら、`appearance` の値を使う（値がないか不明なら `light`）。

### 8.4 テーマの選択肢

v1.0 は、ECharts の本体に入っている `default`（Light）と `dark`（Dark）だけを使う。`theme/` のほかのテーマ（36個）は、ES モジュールで読んだ ECharts にそのままでは登録できない形式のため、v1.x で検討する（1.3節）。0.4 でエンジンを UMD の版にしたので、`theme/` のファイル（UMD）を登録しやすくなる見込みがある。

### 8.5 背景の扱い

- ECharts の既定のテーマは背景を塗らない。`dark` テーマは暗い背景（`rgb(4, 8, 16)` に近い色）を塗る。
- 設定「背景を透明にする」（既定: 有効。D-05）が有効なら、`backgroundColor: 'transparent'` を設定する（利用者が `backgroundColor` を書いた場合は、利用者の指定を優先する）。暗いテーマのノートで、図がノートの背景になじむ。
- **図の有効テーマとページの明暗（`appearance`）が違うときは、SVG の中に背景を塗る**（`option` の `backgroundColor` に、Light の図には `#ffffff`、Dark の図には `#181818` を入れる。色は基準プラグインと同じ）。0.3 では CSS で SVG の後ろに背景を敷くとしていたが、ページの明暗を知るビューアスクリプトがなくなったので変えた。SVG の中に塗るので、エクスポートでも効く（試作の2回目の PDF で、背景が透明な `theme=dark` の図が白い紙でほとんど読めなかった。教訓 2.1節）。
- 利用者が `backgroundColor` を書いた場合は、どの場合も利用者の指定を優先する。`theme=none` の図は、プラグインは背景を変えない。
- SVG は `display: block` にする（行の中に置くと、下に隙間ができるため。試作の段階C で発見）。

### 8.6 CJK のフォント

ECharts は、画面に出さない Canvas で文字の幅を測る。測るときのフォントと表示するときのフォントは、どちらも ECharts が指定する `font-family`（既定は `sans-serif`）で、ブラウザが同じフォントを選ぶので、ずれない（試作の段階B と C で、日本語・中国語・韓国語のはみ出しはなかった）。v1.0 では、フォントを変える設定は作らない（利用者は `option` の `textStyle.fontFamily` で変えられる）。

### 8.7 図の文字サイズ

- **描く幅**（0.4 で変更。D-12 で作者が決めた）: 0.3 では「図の出力の要素の幅で描き、等倍で表示する。ペインの幅が変わったら描き直す」としていたが、Markdown-it の段階ではペインの幅が分からない。次のようにする。
  - 設定「図の幅（px）」（既定 `800`。9章）の幅で描く。ブロックの `width=` で変えられる（6.2節）。
  - SVG に `viewBox` を付け、CSS で `width: 100%; max-width: {描いた幅}px; height: auto` にする。ペインが描いた幅より広ければ等倍で表示し、引き伸ばさない。狭ければ、ペインの幅に合わせて縮めて表示する（文字も縮む）。
  - PDF のエクスポートでは、紙の幅に収まるよう縮む。HTML のエクスポートでも、ブラウザの幅に合わせて縮む。
  - 等倍のまま横スクロールにする案もあったが、狭いペインで図の全体が見えないため採らなかった（D-12）。
- ECharts は描く幅で軸のラベルの間引き（`axisLabel.interval: 'auto'`）を決める。試作の2回目（幅 640px）では、和文の月の名前が1つおきに省かれた。既定の幅を広くすると間引かれにくくなる。利用者は `axisLabel.interval: 0` で全部を出せる（README に書く）。
- **基本の文字サイズ**: 設定「図の文字サイズをノートの本文に合わせる」（既定: 無効。D-05）が有効なら、設定「ノートの本文の文字サイズ」（Joplin の設定 `style.viewer.fontSize` をメインスクリプトが読んで、プラグインの隠し設定に写す。V-10）を `textStyle.fontSize` に入れる。無効なら ECharts の既定（12px）。ECharts のグラフは、題名（18px）、軸の名前、ラベル（12px）などで文字サイズを使い分けており、本文に合わせると全体が大きくなりすぎることがあるため、既定は無効を暫定案とする。`textStyle.fontSize` がどの文字に効くかは段階2 で確かめる（V-01）。
- 利用者が `option` で文字サイズを書いた場合は、利用者の指定を優先する。ただし、最小の文字サイズ（次の項目）は利用者の指定にも効かせる。
- **最小の文字サイズ**（D-05 の作者の要望）: 設定「最小の文字サイズ（px）」（既定 0 = 無効）が 0 より大きいとき、エンジンに渡す前に、`option` の中の `fontSize` の指定のうち最小値より小さいものを最小値に引き上げ、基本の文字サイズ（`textStyle.fontSize`）も最小値以上にする。ECharts は引き上げた文字サイズで配置を計算するので、描いた後に文字だけを拡大する方式と違い、重なりは起きにくい。ECharts が内部で決める文字サイズ（既定 12px）にどこまで効くかは段階2 で確かめる（V-01）。描いた SVG の最小の文字サイズを読み、最小値を下回る文字が残ったら、診断用にコンソールに出す。
- 最小の文字サイズは、描いた幅で表示したときの大きさを保証する。狭いペインで縮めて表示する場合（D-12）は、表示される文字はそれより小さくなる。設定画面の説明に書く。

## 9. 設定画面

Joplin の「設定 → プラグイン」に「dg-echarts」セクションを追加する。ラベルと説明文はすべて翻訳対象とする。

| キー | 型 | 既定値 | 詳細設定 | 説明 |
| ------------------------------- | ------ | ---------------- | -------- | -------------------------------------------------------------------- |
| `echarts.themeMode`             | 列挙   | `auto`           | いいえ   | Auto / Light / Dark（8.2節）                                         |
| `echarts.transparentBackground` | 真偽値 | `true`           | いいえ   | 図の背景を透明にする（8.5節）                                        |
| `echarts.defaultHeight`         | 整数   | `400`            | いいえ   | 図の高さの既定値（px）。ブロックの `height=` が優先                  |
| `echarts.chartWidth` | 整数 | `800` | いいえ | 図を描く幅（px）。範囲は 200〜4000。ブロックの `width=` が優先（8.7節。D-12） |
| `echarts.matchNoteFontSize` | 真偽値 | `false` | いいえ | 図の基本の文字サイズをノートの本文に合わせる（8.7節） |
| `echarts.minFontSizePx` | 整数 | `0` | いいえ | 最小の文字サイズ（px）。`0` で無効（8.7節。D-05） |
| `echarts.showToolbar`           | 真偽値 | `true`           | いいえ   | 図にマウスを乗せたときにツールバーを表示する                         |
| `echarts.editorHighlight`       | 真偽値 | `true`           | いいえ   | Markdown エディタで色分けする（7.7節）                               |
| `echarts.fenceAliases`          | 文字列 | 空               | はい     | 追加の言語名（カンマ区切り。`echarts` は常に有効）                   |
| `echarts.maxSourceLength`       | 整数   | `200000`         | はい     | 描画するソースの最大文字数（試作の段階B の 10.4節の実測を参考に決めた。描画中は表示が待たされるので、V-14 で見直す） |
| `echarts.cacheSize`             | 整数   | `100`            | はい     | 描画の結果のキャッシュの件数                                         |
| `echarts.thirdParty`            | 列挙   | `echarts`        | いいえ   | 同梱している外部のソフトウェアの一覧（表示のためだけ。最下部に置く） |

0.3 にあった `echarts.renderTimeoutMs`（描画時間の上限）は除いた。同期の描画は途中で止められないため（7.3節）。

ほかに、設定画面に出さない隠し設定（`public: false`）を持つ。メインスクリプトが起動時と変更時に Joplin の設定を読んで写し、Markdown-it のプラグインが `settingValue` で読む。

| キー | 写す元 | 用途 |
| --- | --- | --- |
| `echarts.locale` | `joplin.settings.globalValue('locale')` | プラグインの文字列と ECharts のロケール（10.3節） |
| `echarts.noteFontSize` | `joplin.settings.globalValue('style.viewer.fontSize')` | 基本の文字サイズを本文に合わせるとき（8.7節） |

**設定の受け渡し**（0.4 で変更）: Markdown-it のプラグインは、描画のたびに `options.settingValue(key)` で設定値を読む。基準プラグインの `getConfig` の問い合わせと設定版数は使わない。受け取った値は検査し、範囲外や型の違う値は既定値にする（基準の教訓 1.15節）。隠し設定が `settingValue` で読めるか、設定を変えたときに Joplin がノートを描き直すかは、段階1 で確かめる（V-10）。

## 10. 国際化（i18n）

### 10.1 方針

基準プラグイン（10章）と同じ。英語を原文とし、自作の gettext、PO ファイル、11言語（英語、日本語、中国語の簡体字・繁体字、韓国語、ドイツ語、フランス語、スペイン語、ポルトガル語（ブラジル）、イタリア語、ロシア語）。翻訳は Claude が作成し、日本語は作者が確認する。

### 10.2 対象言語

基準プラグインの 10.2節と同じ11言語。

### 10.3 ロケールの決定

- プラグインの文字列: 基準プラグインの 10.3節と同じ（`joplin.settings.globalValue('locale')`、対応表による読み替え、なければ英語）。Markdown-it のプラグインは、隠し設定 `echarts.locale`（9章）からロケールを知る。
- **ECharts のロケール**: 同じ表示言語から、ECharts のロケールを選んで `init` に渡す。日付の軸の月や曜日の名前などに効く（試作で、日本語の月の名前を確認した）。

| Joplin の表示言語                                 | ECharts のロケール                                                                                                             |
| ------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| `en` とそれ以外の未対応の言語                     | `EN`（本体に入っている）                                                                                                       |
| `zh_CN`、`zh_TW` など中国語                       | `ZH`（本体に入っている。簡体字のみ）                                                                                           |
| `ja`、`ko`、`de`、`fr`、`es`、`pt_BR`、`it`、`ru` | `JA`、`KO`、`DE`、`FR`、`ES`、`PT-br`、`IT`、`RU`（`lib/i18n/langXX.js` を同梱し、必要なものだけ読んで `registerLocale` する） |

### 10.4 レンダラーとビューアへの翻訳の受け渡し

- エラーボックスと注意の文字列は、Markdown-it のプラグインが作る。翻訳の表はコンテンツスクリプトに同梱し、`echarts.locale` で選ぶ（0.4 で変更）。
- ツールバーの文字列は、ビューアスクリプトがメインスクリプトに問い合わせて受け取る（基準プラグインの 10.4節と同じ）。

### 10.5 ファイル構成と作業手順、10.6 文字列の書き方の規則

基準プラグインの 10.5節、10.6節と同じ。`locales/echarts.pot` とする。ECharts の設定の名前（`series`、`xAxis` など）は翻訳しない。

## 11. 図の UI

基準プラグイン（11章）と同じく、図にマウスを乗せたとき（キーボードのフォーカス、タップでも）右上にツールバーを出す。

| ボタン                    | 動作                                                                  |
| ------------------------- | --------------------------------------------------------------------- |
| SVG をコピー / SVG を保存 | 無害化した SVG                                                        |
| PNG をコピー / PNG を保存 | SVG を Canvas に2倍の大きさで描いて作る。図の明暗に合わせて背景を塗る |
| ソースをコピー            | ブロックの中身（JSON / YAML）                                         |

- ツールバーはビューアスクリプトが付ける。図そのものは HTML に入っているので、ツールバーは描画と関係なく動く。
- コピーと保存はメインスクリプトが行う（基準の教訓 1.19節）。
- ツールバーはエクスポート（PDF、HTML）に出さない。ビューアスクリプトが付けるものなので HTML には入らないが、念のため CSS の `@media print` でも隠す。
- 図の中のリンクはない（ECharts のリンクは入力の検査で取り除く。12章）。基準プラグインのリンクの処理は作らない。
- アクセシビリティ: Markdown-it のプラグインが、図の出力の要素に `role="figure"` と、翻訳した名前（「ECharts のグラフ」。`title.text` があればそれを加える）を付ける（7.1節）。

## 12. セキュリティ

| 脅威                                            | 対策                                                                                                                                                                                                                                                                                                                                      |
| ----------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| SVG に含まれるスクリプトの実行                  | HTML に入れる前に、Markdown-it のプラグインの中で DOMPurify（SVG のプロファイル）で無害化する（renderer プロセスの `window` を使う。試作の2回目で確認）。入力の文字列の HTML は、ECharts が SVG の中でただの文字として出力する（試作で確認）                                                                                                                                                                                                 |
| 外部の画像の読み込み（外部通信）                | Joplin の CSP は外部の画像を止めないため、プラグインが二重に止める。(1) 入力の検査で、`image://` で始まる文字列とキー `image` を取り除く（画像のパターンは SVG を作る途中で読まれるため、入力の検査が必須）。(2) DOMPurify のフック（`uponSanitizeAttribute`）で、`data:image/` 以外の `<image>` の `href` と、`<a>` の `href` を取り除く |
| ツールチップ、ツールボックスへの HTML の注入    | 静的な SVG では動かないが、入力の検査で `tooltip`、`toolbox` を取り除く                                                                                                                                                                                                                                                                   |
| リンク（`title.link` など）による画面の切り替え | 入力の検査で `link`、`sublink` を取り除く                                                                                                                                                                                                                                                                                                 |
| JavaScript の関数の実行                         | 入力を JavaScript として評価しない（JSON / YAML の解析だけ）。CSP でも `eval` は使えない                                                                                                                                                                                                                                                  |
| YAML の別名の巨大な展開                         | 別名の展開の数に上限を設ける（6.3節）                                                                                                                                                                                                                                                                                                     |
| 巨大な入力によるフリーズ                        | 最大文字数を設ける。試作では、1万件のデータでも固まらなかった（最も遅い1万切れの円グラフで 1.8 秒）。描画は同期的で止められず、描いている間はノートの表示全体が待たされる（7.3節、V-14） |
| エンジンのエラーメッセージに含まれる HTML       | HTML としてエスケープしてから HTML の文字列に入れる（試作の2回目で、悪意のある文字列がただの文字になることを確認） |
| エクスポートした HTML からの外部通信            | 図は無害化した SVG として HTML に入っているだけで、スクリプトもエンジンのファイルも参照しない。外部の URL の画像は入力の検査と DOMPurify で取り除いてある |
| ノート内容の外部送信                            | 通信を一切行わない。依存ライブラリにも通信しないものだけを使う                                                                                                                                                                                                                                                                            |

**入力の検査の規則**（`inputGuard.ts`）: 入力のオブジェクト全体を走査し、次に当たる値を取り除く。場所を決め打ちにしない（ECharts の設定の項目は非常に多いため）。

| 種類                         | 対象                                                           | 注意を出すか                                                             |
| ---------------------------- | -------------------------------------------------------------- | ------------------------------------------------------------------------ |
| 静的な図では効果がないもの   | キー `tooltip`、`toolbox`、`link`、`sublink`、`axisPointer`    | 出さない（公式の例の多くに含まれ、注意が出ると不具合と受け取られるため） |
| 取り除くと見た目が変わるもの | `image://` で始まる文字列（`path://` は残す）、キー `image`    | 出す                                                                     |
| 対象外の機能                 | 地図（`geo`、`series.type: 'map'`、`coordinateSystem: 'geo'`） | エラーにする                                                             |

- 取り除く方式（禁止リスト）なので、ECharts の版を更新するときに、新しい項目で外部の URL を読む経路が増えていないかを確かめる（`vendor/echarts/SOURCE.md` の更新手順に書く）。
- `data:` の URL の画像を許すかは、許さないと決めた（D-10）。

## 14. プラットフォームと表示箇所

基準プラグイン（14章）と同じ。v1.0 はデスクトップのノートビューア、Markdown エディタ（構文ハイライト）、リッチテキストエディタ（Mermaid と同じ扱い。試作の段階C の1回目と2回目で確認）、**エクスポート（PDF、HTML）**（D-04）。モバイルは v1.x。

| 場面 | 図が出るか | 根拠 |
| --- | --- | --- |
| ノートビューア | 出る | 試作の2回目 |
| リッチテキストエディタ | 出る（編集の画面とソースの往復も問題なし） | 試作の2回目 |
| PDF のエクスポート | 出る（ベクターの SVG。Auto の図は明るい配色） | 試作の2回目 |
| HTML のエクスポート | 出る（SVG が HTML に入っている。エンジンのファイルは要らない） | 試作の2回目 |
| 印刷 | **出ない**（普通のコードブロックになる） | Joplin の問題（下記） |

**印刷**: Joplin のデスクトップ版は、印刷のときにプラグインの Markdown-it のコンテンツスクリプトを読み込まない（`usePrintToCallback.ts` の `printNote` の呼び出しが `plugins` を渡していない。PDF のエクスポートは渡している。教訓 1.4節）。プラグインでは直せないので、次のようにする。

- README と CHANGELOG に「印刷するときは、PDF にエクスポートしてから印刷してください」と書く。
- Joplin には報告しない（issue も PR も出さない。D-13 で作者が決めた）。修正は1行で済む見込みであることは記録に残す（教訓 1.4節）。
- Joplin が直したら、印刷でも図が出る（プラグインの変更は要らない）。

**改ページ**: 図の要素（`.joplin-echarts`）に `break-inside: avoid` を付け、図がページの途中で切れないようにする（試作の2回目の PDF で、見出しだけがページの下に残り、図が次のページに回った。見出しと図を離さない方法は段階1 で検討する）。

**PDF の文字**: 試作の2回目の PDF で、ラベルの文字を取り出すと二重になった（教訓 2.2節）。段階1 で原因を確かめる（V-11）。

### 14.1 モバイル対応の見通し

### 15.1 配布パッケージ

- エンジンは `.jpl` に内蔵する。
- **エンジン**（D-09）: `vendor/echarts/echarts.min.js`（公式の UMD の圧縮版。取得元とバイト単位で同じ）と、ロケールのファイル（`langXX.js`）を、ビルドでそのまま `dist/contentScript/engine/` にコピーする。コピーの設定に `info: { minimized: true }` を付け、圧縮し直さない（基準の教訓 1.8節）。取得元、版、SHA-256 を `vendor/echarts/SOURCE.md` に記録し、テストで `.jpl` の中のエンジンが `vendor/` と同じであることを確かめる。
- 0.3 では ES モジュールの `echarts.esm.min.mjs` をビューアスクリプトが `import()` で読む形だった。0.4 で、Markdown-it のコンテンツスクリプトが Node の `require` で読む形にしたので、UMD の版に変える（UMD は `module.exports` があるとそこに書き出し、グローバル変数を作らない）。試作の2回目は、npm の `echarts` を webpack でコンテンツスクリプトにまとめていたので、`require` で読む形は段階1 の最初に確かめる（V-13）。読めない場合は、`vendor/` の圧縮版を webpack でまとめ、圧縮し直さずに取り込む方法を検討し、作者に相談する（D-09 の見直し）。
- コンテンツスクリプトは、DOMPurify と `yaml` を含めて webpack でまとめる。ビューアスクリプト（ツールバーだけ）は別にまとめる（基準プラグインの `webpack.viewer.js` と同じ方法）。
- `.gitattributes` に `vendor/** -text` を書く（作成済み）。
- `.jpl` には `LICENSE`、`THIRD_PARTY_NOTICES*.md`、エンジンのライセンス文を含める。

## 16. テスト方針

開発の指示文書の「04 テスト」と、基準プラグインの 16章と同じ構成にする。違いは次のとおり。

- **単体テスト**: 基準プラグインの項目に加え、入力の解析（JSON / YAML の行番号、大きさの上限、YAML の別名の上限）、入力の検査（取り除く項目、注意を出すかどうか、正しい入力は変わらないこと）、プラグインの検査（7.4節の誤り）、最小の文字サイズの引き上げ、ECharts のロケールの選択、乱数の種の固定が元に戻ること。
- **描画テスト**（ヘッドレスの Chrome）: 試作の段階B のケース（20 種類の図、CJK、テーマ、悪意のある入力、外部の画像、誤った入力、大きな入力）を正式なテストにする。各図を単独で描いた結果と、ほかの図に続けて描いた結果が一致すること。0.4 の方式に合わせ、ページの中で Markdown-it とプラグインを動かして HTML を作り、その HTML をページに入れて確かめる（Joplin の renderer プロセスと同じく、`window` と Canvas がある環境で描く）。`appearance` が `light` と `dark` のとき、エクスポートを模した options のときの出力も比べる。
- **テスト用のページの CSP**: Joplin 3.7.24 の CSP と同じにする（4.1節）。外部への要求はルートの記録（`context.route`）で検出する。入力の検査を外すと外部の画像の要求が記録されることを確かめる（検査そのものを試すテスト）。
- **エンジンの同一性のテスト**: `.jpl` の中のエンジンとロケールのファイルが、`vendor/` のものと SHA-256 で一致すること（15.1節）。
- **エクスポートと印刷**: 手動テストに、PDF と HTML のエクスポートで図が出ることを加える（M-17）。暗いテーマのまま書き出して明るい配色になること、`theme=dark` の図が読めること、PDF から文字を正しく取り出せること（V-11）、図がページの途中で切れないことも見る。HTML のエクスポートは、書き出した HTML をブラウザで開き、通信が起きないこと、外部のファイルを参照しないことも確かめる。印刷は、Joplin の問題で図が出ないことを確かめ、Joplin の新しい版で直ったかを見る（M-18）。
- **手動テスト**: 基準プラグインの M-01〜M-16 を使う。M-11（図の中のリンク）は、リンクを扱わないので除く。

| D-09 | 同梱するエンジンの形 | **公式の圧縮版をそのまま同梱する**（取得元のファイルと同じであることを SHA-256 で確かめられる）。誤った入力のメッセージは、プラグインが自分で検査して出す（7.4節）。0.4 で、描画の方式に合わせて、ES モジュールの版から UMD の版（`echarts.min.js`）に変えた（どちらも公式の圧縮版で、方針は変わらない）。`require` で読めなければ見直す（V-13） |
| D-10 | `data:` の URL の画像を許すか | 許さない（要望があれば v1.x で検討する） |
| D-11 | 公開するか | リリースできる品質になった時点で、作者が判断する |
| D-12 | 図の幅（0.4 で追加） | **設定の幅（既定 800px）で描き、ペインがそれより狭ければ縮めて表示する（引き伸ばしはしない）。ブロック単位の `width=` を加える**（暫定案どおり。2026-11-23）。Markdown-it の段階ではペインの幅が分からないので、0.3 の「表示する幅で描き、縮小しない」は実現できないため。等倍のまま横スクロールにする案は採らなかった（6.2節、8.7節、9章） |
| D-13 | 印刷の問題を Joplin に報告するか（0.4 で追加） | **報告しない。README で「PDF にエクスポートしてから印刷する」と案内する**（暫定案どおり。2026-11-23）。issue と修正の PR（`usePrintToCallback.ts` の `printNote` の呼び出しに `plugins: props.plugins` を加える1行の見込み）は出さない。Joplin が直したかは手動テスト（M-18）で見る（14章） |

基準プラグインで決まっていて、変える理由のない事項は、決定済みとして扱う: ライセンス（MIT）、最低対応バージョン（Joplin 3.1）、翻訳の体制（10章）、`author`（`akira tamcat`）、連絡は GitHub で受け付ける、GitHub のリポジトリ名は npm パッケージ名と同じ。
