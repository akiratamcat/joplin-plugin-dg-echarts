## 1. 概要

### 1.1 目的

Joplin のノート（Markdown）に書かれた ECharts のコードブロックを、Joplin 本体のノートビューア上で図（SVG）として表示するプラグインを提供する。

Joplin 本体は Mermaid をサポートしており、` ```mermaid ` と書くだけで図が表示される。本プラグインは **「インストールするだけで、Mermaid と同等の使い勝手で Apache ECharts のグラフが使える」** ことを目標とする。ECharts は、Mermaid の `xychart` や `pie` よりはるかに多くの種類のグラフ（散布図、レーダー、ヒートマップ、ツリーマップ、サンキー、ローソク足、箱ひげなど）を描ける。

### 1.2 設計方針

1. **ゼロ設定で動く**: インストール直後から、追加のソフトウェアや設定なしで描画できる。
2. **オフライン・外部通信なし**: ECharts を同梱してローカルで実行する。本プラグインはネットワーク通信を一切行わず、ノートの内容を外部に送らない。Joplin のノートビューアの CSP は外部の画像を止めない（4.1節）ので、外部の URL はプラグインが取り除く（12章）。これを主なアピールポイントとして、公開する場で明記する（21.7節）。
3. **Joplin の流儀に従う**: Markdown-it コンテンツスクリプト、`joplin-editable` 構造、設定 API、テーマなど、Joplin 本体および Mermaid 実装と同じ仕組み・見た目に揃える。
4. **最初から国際化**: UI 文字列はすべて gettext と PO ファイルで管理する。
5. **テーマは Joplin に合わせる**: 図の配色（Light / Dark）は、既定では Joplin のテーマの明暗に自動で合わせる。設定画面で固定することもできる。
6. **MIT ライセンスで、エンジンを内蔵して配布する**: 本プラグインは MIT ライセンスとし、ECharts（Apache-2.0）をプラグインに内蔵して配布する（20章）。
7. **公開を前提に作る**: リリースできる品質になったら、GitHub で公開し、GitHub Releases と npm でリリースして、Joplin 公式プラグイン一覧に掲載する（21章。作者の方針: リリースできそうなら公開する）。
8. **生成 AI の利用を明記する**: 本プラグインは生成 AI（Anthropic の Claude）を全面的に用いて開発する。作者が出力を確認して管理していることと合わせて、README などに明記する（22章）。

## 4. 前提となる技術要素

### 4.1 Joplin プラグインの仕組み

本プラグインで使う Joplin プラグイン API は、基準プラグイン（4.1節）と同じ。

| API                                                                              | 用途                                                                           |
| -------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| `joplin.contentScripts.register(ContentScriptType.MarkdownItPlugin, id, path)`   | Markdown-it プラグインとアセットの登録                                         |
| `joplin.contentScripts.register(ContentScriptType.CodeMirrorPlugin, id, path)`   | Markdown エディタへの構文ハイライト拡張の登録                                  |
| `joplin.contentScripts.onMessage(id, handler)`                                   | ビューアスクリプトからの問い合わせ（設定・翻訳の取得、コピーと保存）に応答する |
| `webviewApi.postMessage(id, message)`（ビューア側）                              | メインスクリプトへの問い合わせ                                                 |
| `joplin.settings.registerSection` / `registerSettings` / `value` / `globalValue` | 設定画面、設定値、Joplin のロケール                                            |
| `joplin.clipboard`、`joplin.views.dialogs`、`joplin.require('fs-extra')`         | 図のコピーと保存（11章）                                                       |
| ビューアのイベント `joplin-noteDidUpdate`                                        | ノート本文の再描画後に処理を開始する合図                                       |

最低対応バージョン（`app_min_version`）は **Joplin 3.1** とする（基準プラグインと同じ根拠。動作確認は最新の安定版で行う）。

**ノートビューアの CSP**（試作の段階C で、Joplin 3.7.24 で実測）:

```text
default-src 'self' ; img-src 'self' blob: data: * ; media-src 'self' blob: data: * ;
child-src https://*.youtube.com https://*.youtube-nocookie.com ; object-src 'none' ;
form-action 'none' ; style-src 'self' 'unsafe-inline' * data:
```

- `eval`、`new Function`、WebAssembly は使えない。Web Worker は作れない（基準の教訓 1.1節）。
- **`img-src` と `style-src` に `*` があり、外部の画像は CSP では止まらない**。外部の画像を止めるのはプラグインの役目になる（12章）。
- `style-src` に `'unsafe-inline'` があり、SVG の `style` 属性と `<style>` 要素は効く。
- ページは `about:`、プラグインのファイルは `file:` の URL で読み込まれる。

### 4.2 Apache ECharts

**採用**: Apache ECharts **6.1.0**（2026-05-19 公開、Apache-2.0）。作者が試作の結果を受けて決定した（2026-11-23）。以後の更新は 19章 D-07 の方針による。6.1.0 未満には XSS の脆弱性（GHSA-fgmj-fm8m-jvvx）があるため、6.1.0 未満には戻さない。

**選んだ理由**（エンジンの選定は作者の非公開の作業用リポジトリで行った。要点だけを書く）: 必須の条件（ブラウザだけで動く、WASM・Worker・動的なコード生成を使わない、外部通信を止められる、ライセンス）をすべて満たし、SVG を文字列で作る API があり、Dark のテーマと多くの言語のロケールを内蔵し、Apache 財団のプロジェクトで保守が安定している。

**使い方の要点**:

| 項目       | 内容                                                                                                                                                                                                                                                 |
| ---------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 描き方     | `echarts.init(null, テーマ, { renderer: 'svg', ssr: true, width, height, locale })` で描画先のないインスタンスを作り、`setOption(option)` のあと `renderToSVGString()` で SVG の文字列を得て、`dispose()` する。DOM を使わないので、表示前でも描ける |
| 同梱する版 | 公式の開発版 `dist/echarts.esm.mjs` を esbuild で圧縮したもの（約 1.16MB）。公式の圧縮版と図の出力は同じで、誤った入力のメッセージが残る（D-09。15.1節）                                                                                             |
| テーマ     | `default`（明るい）と `dark` が本体に入っている                                                                                                                                                                                                      |
| ロケール   | 本体には英語と中国語だけ。ほかの言語は `lib/i18n/langXX.js` を登録して使う（10.3節）                                                                                                                                                                 |
| 文字の幅   | 画面に出さない Canvas の `measureText` で測る。日本語なども正しく測れた                                                                                                                                                                              |

**試作の結果の要約**（詳細は `docs/spike-results.ja.md`。試作のコードは `spike/engine`、`spike/plugin` ブランチにある）:

| 段階                     | 主な結果                                                                                                                                                                                                   |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A（調査）                | ライセンスは Apache-2.0。d3.js の一部（BSD-3-Clause）を取り込んでいる。Worker、WASM、通信の API はない。動的なコード生成は地図の古い経路の1か所だけで、描画では通らない。ES モジュールの形は全部入りだけ   |
| B（ヘッドレスの Chrome） | 20 種類の図がすべて描けた。日本語・中国語・韓国語ははみ出さない。読み込み 100〜125ms、2回目以降の描画 1〜13ms。グローバル変数を作らず、ページに要素を足さない。悪意のある文字は SVG の中でただの文字になる |
| C（Joplin 3.7.24）       | Markdown のビューアとリッチテキストエディタで描けた。ソースの往復と編集画面も問題なし。テーマの切り替えに追従した。SVG の `style` 属性と `<style>` 要素が効いた                                            |

**試作で分かった注意点と、本設計での対応**:

| 注意点                                                                                                                                                                                                               | 対応                                                                                       | 参照  |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ | ----- |
| 画像のパターン（`{ image, repeat }`）は SVG を作る途中で `new Image()` で読まれる。シンボルなどの画像は SVG の `<image href>` として出力される。DOMPurify の SVG のプロファイルは外部の URL の `<image href>` を残す | 入力の検査で取り除き、DOMPurify のフックでも取り除く（二重）                               | 12章  |

| 一部のメッセージは、ページの中で1回しか出ない（`onlyOnce`）                                                                                                                                                          | 描画の結果のキャッシュにメッセージも入れる                                                 | 7.4節 |
| 力学モデルのグラフは乱数で配置を決め、既定では配置の計算を `setTimeout` で少しずつ進める                                                                                                                             | 描画の間だけ `Math.random` を固定の種の乱数にし、`force.layoutAnimation: false` を設定する | 7.5節 |
| 既定のテーマは背景を塗らない。`dark` テーマは暗い背景を塗る                                                                                                                                                          | 背景の扱いを決める                                                                         | 8.5節 |
| ほぼすべての SVG に、強調表示の `<style>` が入る（クラス名は図ごとに違う）                                                                                                                                           | 残してよい                                                                                 | 12章  |
| 静的な図ではツールチップなどは働かない。公式の例の多くに `tooltip` がある                                                                                                                                            | 注意を出さずに取り除く                                                                     | 12章  |

## 5. アーキテクチャ

### 5.1 構成

基準プラグインと同じく、描画は **ビューア内で実行する**。Markdown-it プラグインはプレースホルダの HTML を出力するだけにし、エンジンの処理はビューアスクリプトが非同期で行う。描画の流れは、エンジンが SVG の文字列を返し、それを無害化して挿入する「文字列型」である。

```text
Markdown エディタ ─(ノート本文)→ Markdown レンダラー ─(fence)→ Markdown-it コンテンツスクリプト
                                                                     │ プレースホルダ HTML + アセット
                                                                     ▼
            ノートビューア: ビューアスクリプト ─(option)→ ECharts エンジン ─(SVG の文字列)→ 無害化 → 挿入
                               │  ↑ キャッシュ（LRU）
                               └─ postMessage ─→ メインスクリプト（設定、翻訳、コピー・保存）
Markdown エディタ ← CodeMirror コンテンツスクリプト（JSON / YAML の色分け）
```

### 5.2 描画シーケンス

1. 利用者がノートを開く・編集する。Joplin のレンダラーが Markdown-it プラグインを呼ぶ。
2. Markdown-it プラグインが、` ```echarts ` のブロックをプレースホルダの HTML にする（7.1節）。
3. Joplin が本文を差し替え、`joplin-noteDidUpdate` を送る。
4. ビューアスクリプトが、メインスクリプトに設定を問い合わせる（初回だけ待つ）。
5. ビューアスクリプトが有効テーマと描画の幅を決める。
6. 未描画のブロックごとに、キャッシュキーを計算し、キャッシュがあれば挿入する。なければ、入力を解析し（JSON / YAML）、入力の検査をして、エンジンで描き、無害化して挿入し、キャッシュに保存する。

### 5.3 モジュール一覧

基準プラグインの構成を借りる。PlantUML に固有の `preamble.ts` は作らない。

## 6. 記法の仕様

### 6.1 対象とするコードブロック

````markdown
```echarts
{
  "xAxis": { "type": "category", "data": ["Mon", "Tue", "Wed"] },
  "yAxis": {},
  "series": [{ "type": "bar", "data": [120, 200, 150] }]
}
```
````

| 項目                       | 仕様                                                                                                                                           |
| -------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| 言語名                     | `echarts`（大文字・小文字は区別しない）。設定で別名を追加できる                                                                                |
| 中身                       | ECharts の `option`。JSON で書く。YAML も受け付けるかは D-02（暫定案: 受け付ける。6.3節）                                                      |
| 1ブロック内の図            | 1つ                                                                                                                                            |
| フェンスの長さ、インデント | 基準プラグインと同じ（3文字以上、閉じフェンスは同じ文字で同じ長さ以上。リッチテキストエディタの編集画面で OK を押すと3文字に組み立て直される） |

### 6.2 ブロック単位のオプション

| オプション | 値                          | 説明                                                                                                             |
| ---------- | --------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| `theme`    | `light` / `dark` / `none`   | このブロックだけテーマを指定する。`none` は ECharts の既定のテーマで描き、プラグインは背景も文字サイズも変えない |
| `align`    | `left` / `center` / `right` | 図の配置（既定は `center`）                                                                                      |
| `height`   | 数（px）                    | 図の高さ。ECharts は高さを入力から決めないため。既定は設定の値（暫定案 400）。範囲は 100〜2000                   |

どれを入れるかは D-03（暫定案: 3つとも入れる）。不明なオプションは無視する。

### 6.3 入力の形式

- **JSON**: 中身の最初の空白でない文字が `{` なら JSON として解析する（`JSON.parse`）。構文の誤りは、例外のメッセージの位置から行番号を出す。
- **YAML**（D-02 で受け付ける場合）: それ以外は YAML として解析する（`yaml` パッケージ。ISC）。コメントが書け、引用符をほとんど省けるので、手で書きやすい。YAML の別名（`*name`）の展開には上限を設け（`maxAliasCount`）、巨大な展開を防ぐ。構文の誤りは、パーサーが返す行番号を出す。
- 解析した結果は、オブジェクト（`{}`）でなければエラーにする。
- **関数は書けない**: 入力を JavaScript として評価しない。`formatter` の関数などは使えない（文字列のテンプレート `'{b}: {c}'` は使える）。README の「制限事項」に書く。

YAML の例:

````markdown
```echarts
# 月別の売上
xAxis: { type: category, data: [1月, 2月, 3月] }
yAxis: {}
series:
  - type: bar
    data: [120, 200, 150]
```
````

## 7. 描画処理の詳細

### 7.1 Markdown-it プラグインの出力

基準プラグイン（7.1節）と同じ形にする（試作の段階C で、リッチテキストエディタとの往復と編集画面で問題がないことを確認した）。

```html
<div class="joplin-editable joplin-echarts">
  <pre class="joplin-source"
       data-joplin-language="{info 文字列}"
       data-joplin-source-open="{開きフェンス}{info 文字列}&#10;"
       data-joplin-source-close="&#10;{閉じフェンス}">{エスケープ済みソース（末尾の改行を1つ除く）}</pre>
  <div class="joplin-echarts-output" aria-busy="true"></div>
</div>
```

- 末尾の改行を1つ除き、閉じフェンスを改行から始める。`data-joplin-language` に info 文字列全体を入れる（基準の教訓 1.4節）。
- アセットとして宣言するのは `viewer.js` と CSS だけ。エンジンのファイルは宣言しない（基準の教訓 1.3節）。

### 7.2 ビューアスクリプトの処理の流れ

基準プラグイン（7.2節）と同じ。違いは次のとおり。

- 描画済みの印は、図の出力の要素（`.joplin-echarts-output`）に付ける。
- キャッシュキーは `hash(ソース + 有効テーマ + 描画の幅 + 高さ + 基本文字サイズ + ロケール + 設定版数 + エンジン版数)`。
- **描画の幅**: 図の出力の要素の幅で描く（8.7節）。幅が変わったら（`ResizeObserver`）、デバウンスして描き直す。幅はキャッシュキーに入る。
- 描画の結果（SVG、注意、ECharts のメッセージ）をまとめてキャッシュに入れる（7.4節）。

### 7.3 ちらつき対策（編集中の再描画）

基準プラグイン（7.3節）と同じ（キャッシュ、直前の図を残す、デバウンス 300ms、直列キュー、タイムアウトの表示）。ECharts の描画は 1〜13ms と速いので、効果は主にキャッシュとデバウンスによる。

### 7.4 エラー表示

| 場合                                                  | 表示                                                                   |
| ----------------------------------------------------- | ---------------------------------------------------------------------- |
| JSON / YAML の構文の誤り                              | エラーボックスに、メッセージと行番号と該当行の抜粋（色分けつき）を出す |
| 中身がオブジェクトでない、大きさの上限を超えた        | エラーボックス                                                         |
| 地図（`geo`、`series.type: 'map'`）を使っている       | エラーボックス（「地図は使えない」）。エンジンに渡す前に検出する       |
| エンジンの例外（例: `xAxis "0" not found`）           | エラーボックスに ECharts のメッセージを出す（行番号はない）            |
| エンジンの警告（例: `Unknown series ...`）            | 図の下に注意として出す。図は描く                                       |
| 描けるものがない（`series` がない、すべて未知の種類） | 空の図ではなく、「描くものがありません」と注意を出す                   |
| 入力の検査で、見た目が変わる項目を取り除いた          | 図の下に注意（「外部の画像は表示しません」など）                       |

- エンジンの警告は、描画の間だけ `console.warn` と `console.error` を受け取って集める。ECharts は一部のメッセージをページの中で1回しか出さないので、描画の結果のキャッシュにメッセージも入れ、描き直しても表示する（試作の段階C で発見）。
- ECharts のメッセージは英語のまま表示する。
- エンジンから来た文字は `textContent` で入れる。
- 編集中にエラーになったときは、エラーボックスの下に直前の図を半透明で残す（基準プラグインと同じ）。

### 7.5 エンジンの読み込みと呼び出し

- 最初の ECharts のブロックを見つけたときに、`import(/* webpackIgnore: true */ engine/echarts.mjs)` で読み込む（遅延読み込み）。ロケールのファイルも、必要な1つだけを読む。
- メインスレッドで動かす（Worker は作れない）。
- 呼び出しのたびに、`init`、`setOption`、`renderToSVGString`、`dispose` を行う。インスタンスは使い回さない。
- **同じ入力から同じ図にする**: 描画の間だけ `Math.random` を固定の種の乱数（mulberry32 など）に置き換え、`finally` で必ず元に戻す。`series` のうち `type: 'graph'` かつ `layout: 'force'` のものには `force.layoutAnimation: false` を設定する。
- アニメーションは無効にする（`animation: false`）。

### 7.6 エンジン抽象化インターフェース

開発の指示文書の共通の形（`RenderEngine`）を使う。

```ts
interface RenderEngine {
  readonly name: string;      // "echarts"
  readonly version: string;   // "6.1.0"。キャッシュキーに含める
  readonly output: 'svg';
  init(): Promise<void>;
  render(option: object, opts: RenderOptions): Promise<RenderResult>;
}

interface RenderOptions {
  timeoutMs: number;
  theme: 'light' | 'dark' | 'none';
  width: number;
  height: number;
  baseFontSize: number | null; // null はエンジンの既定（12px）
  locale: string;              // ECharts のロケール（"JA" など）
}

type RenderResult =
  | { ok: true; output: string; warnings: string[] }
  | { ok: false; reason: RenderFailure; message: string; line?: number };

type RenderFailure = 'syntax' | 'invalid' | 'blocked' | 'crash' | 'timeout' | 'engine';
```

- 入力の解析（`syntax`）と入力の検査は、エンジンを呼ぶ前に `controller.ts` が行う。`blocked` は地図など、禁止した機能を使っている場合。
- `warnings` には、ECharts の警告と、入力の検査で取り除いた項目のうち注意を出すものを入れる。

### 7.7 Markdown エディタでの構文ハイライト

基準プラグイン（7.7節）の仕組み（`ViewPlugin` と `Decoration.mark`、エディターのテーマの色、見えている範囲だけ）を使い、字句解析を JSON / YAML 用にする。

| 種類             | 例                          | ハイライトタグ  |
| ---------------- | --------------------------- | --------------- |
| キー             | `"series"`、`xAxis:`        | `propertyName`  |
| 文字列           | `"bar"`                     | `string`        |
| 数値             | `120`、`-1.5e3`             | `number`        |
| 真偽値・null     | `true`、`null`              | `bool` / `null` |
| コメント（YAML） | `# 月別`                    | `comment`       |
| 記号             | `{` `}` `[` `]` `:` `,` `-` | 色分けしない    |

ECharts に固有の語（`series` の種類の名前など）は色分けしない。

## 8. テーマとスタイル

### 8.1 ECharts 側のスタイル手段

| 手段                 | 例                        | 本プラグインでの使い方                                    |
| -------------------- | ------------------------- | --------------------------------------------------------- |
| テーマ               | `init(null, 'dark')`      | 有効テーマが Dark のとき `dark`、Light のとき既定のテーマ |
| `backgroundColor`    | `'transparent'`           | 背景の扱い（8.5節）                                       |
| `textStyle.fontSize` | `14`                      | 基本の文字サイズ（8.7節）                                 |
| 利用者の `option`    | `color`、`itemStyle` など | プラグインは変えない。利用者の指定が優先される            |

### 8.2 テーマモード

基準プラグインと同じく、設定 `themeMode` で Auto（既定）/ Light / Dark を選ぶ。Auto は、ビューアの背景色の相対輝度で明暗を判定する（試作の段階C で、Joplin 3.7.24 の暗いテーマ `rgb(29, 32, 36)` を `dark` と判定できた）。Joplin のテーマを切り替えるとビューアが読み込み直されるので、判定し直される。

### 8.3 有効テーマの決定

1. ブロックに `theme=` の指定があれば、それを使う。
2. なければ、設定 `themeMode` が Light / Dark ならその値を使う。
3. Auto なら、ビューアの背景色から判定した値を使う。

### 8.4 テーマの選択肢

v1.0 は、ECharts の本体に入っている `default`（Light）と `dark`（Dark）だけを使う。`theme/` のほかのテーマ（36個）は、ES モジュールで読んだ ECharts にそのままでは登録できない形式のため、v1.x で検討する（1.3節）。

### 8.5 背景の扱い

- ECharts の既定のテーマは背景を塗らない。`dark` テーマは暗い背景（`rgb(4, 8, 16)` に近い色）を塗る。
- 設定「背景を透明にする」（暫定案: 有効。D-05）が有効なら、`backgroundColor: 'transparent'` を設定する（利用者が `backgroundColor` を書いた場合は、利用者の指定を優先する）。暗いテーマのノートで、図がノートの背景になじむ。
- **図とページの明暗が違うときは、CSS で SVG の後ろに背景を敷く**（Light の図には `#ffffff`、Dark の図には `#181818`。基準プラグインと同じ）。試作の段階C で、暗いテーマの `theme=light` の図が読めることを確認した。
- SVG は `display: block` にする（行の中に置くと、下に隙間ができて背景が帯のように見えるため。試作の段階C で発見）。

### 8.6 CJK のフォント

ECharts は、画面に出さない Canvas で文字の幅を測る。測るときのフォントと表示するときのフォントは、どちらも ECharts が指定する `font-family`（既定は `sans-serif`）で、ブラウザが同じフォントを選ぶので、ずれない（試作の段階B と C で、日本語・中国語・韓国語のはみ出しはなかった）。v1.0 では、フォントを変える設定は作らない（利用者は `option` の `textStyle.fontFamily` で変えられる）。

### 8.7 図の文字サイズ

- **縮小表示しない**: 図は、図の出力の要素の幅で描き、等倍で表示する（SVG の `viewBox` による縮小に頼らない）。文字は ECharts が指定した大きさで表示されるので、最小文字サイズの計算（基準プラグインの 8.7節の (2)）はいらない。ペインの幅が変わったら描き直す（7.2節）。
- **基本の文字サイズ**: 設定「図の文字サイズをノートの本文に合わせる」（暫定案: 無効。D-05）が有効なら、ビューアの本文の文字サイズを `textStyle.fontSize` に入れる。無効なら ECharts の既定（12px）。ECharts のグラフは、題名（18px）、軸の名前、ラベル（12px）などで文字サイズを使い分けており、本文に合わせると全体が大きくなりすぎることがあるため、既定は無効を暫定案とする。`textStyle.fontSize` がどの文字に効くかは段階2 で確かめる（V-01）。
- 利用者が `option` で文字サイズを書いた場合は、利用者の指定を優先する。
- 幅が非常に狭い（200px 未満）場合は 200px で描き、横スクロールにする。

| ------------------------- | --------------------------------------------------------------------- |
| SVG をコピー / SVG を保存 | 無害化した SVG                                                        |
| PNG をコピー / PNG を保存 | SVG を Canvas に2倍の大きさで描いて作る。図の明暗に合わせて背景を塗る |
| ソースをコピー            | ブロックの中身（JSON / YAML）                                         |

- コピーと保存はメインスクリプトが行う（基準の教訓 1.19節）。
- 図の中のリンクはない（ECharts のリンクは入力の検査で取り除く。12章）。基準プラグインのリンクの処理は作らない。
- アクセシビリティ: 図の出力の要素に `role="figure"` と、翻訳した名前（「ECharts のグラフ」。`title.text` があればそれを加える）を付ける。

## 12. セキュリティ

| 脅威                                            | 対策                                                                                                                                                                                                                                                                                                                                      |
| ----------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| SVG に含まれるスクリプトの実行                  | 挿入前に DOMPurify（SVG のプロファイル）で無害化する。入力の文字列の HTML は、ECharts が SVG の中でただの文字として出力する（試作で確認）                                                                                                                                                                                                 |
| 外部の画像の読み込み（外部通信）                | Joplin の CSP は外部の画像を止めないため、プラグインが二重に止める。(1) 入力の検査で、`image://` で始まる文字列とキー `image` を取り除く（画像のパターンは SVG を作る途中で読まれるため、入力の検査が必須）。(2) DOMPurify のフック（`uponSanitizeAttribute`）で、`data:image/` 以外の `<image>` の `href` と、`<a>` の `href` を取り除く |
| ツールチップ、ツールボックスへの HTML の注入    | 静的な SVG では動かないが、入力の検査で `tooltip`、`toolbox` を取り除く                                                                                                                                                                                                                                                                   |
| リンク（`title.link` など）による画面の切り替え | 入力の検査で `link`、`sublink` を取り除く                                                                                                                                                                                                                                                                                                 |
| JavaScript の関数の実行                         | 入力を JavaScript として評価しない（JSON / YAML の解析だけ）。CSP でも `eval` は使えない                                                                                                                                                                                                                                                  |
| YAML の別名の巨大な展開                         | 別名の展開の数に上限を設ける（6.3節）                                                                                                                                                                                                                                                                                                     |
| 巨大な入力によるフリーズ                        | 最大文字数を設ける。試作では、1万件のデータでも固まらなかった（最も遅い1万切れの円グラフで 1.8 秒）。タイムアウトでは表示をエラーに切り替えるだけで、描画は止められない                                                                                                                                                                   |
| エンジンのエラーメッセージに含まれる HTML       | `textContent` で挿入する                                                                                                                                                                                                                                                                                                                  |
| ノート内容の外部送信                            | 通信を一切行わない。依存ライブラリにも通信しないものだけを使う                                                                                                                                                                                                                                                                            |

**入力の検査の規則**（`inputGuard.ts`）: 入力のオブジェクト全体を走査し、次に当たる値を取り除く。場所を決め打ちにしない（ECharts の設定の項目は非常に多いため）。

| 種類                         | 対象                                                           | 注意を出すか                                                             |
| ---------------------------- | -------------------------------------------------------------- | ------------------------------------------------------------------------ |
| 静的な図では効果がないもの   | キー `tooltip`、`toolbox`、`link`、`sublink`、`axisPointer`    | 出さない（公式の例の多くに含まれ、注意が出ると不具合と受け取られるため） |
| 取り除くと見た目が変わるもの | `image://` で始まる文字列（`path://` は残す）、キー `image`    | 出す                                                                     |
| 対象外の機能                 | 地図（`geo`、`series.type: 'map'`、`coordinateSystem: 'geo'`） | エラーにする                                                             |

- 取り除く方式（禁止リスト）なので、ECharts の版を更新するときに、新しい項目で外部の URL を読む経路が増えていないかを確かめる（`vendor/echarts/SOURCE.md` の更新手順に書く）。
- `data:` の URL の画像を許すかは D-10（暫定案: 許さない）。

## 16. テスト方針

開発の指示文書の「04 テスト」と、基準プラグインの 16章と同じ構成にする。違いは次のとおり。

- **単体テスト**: 基準プラグインの項目に加え、入力の解析（JSON / YAML の行番号、大きさの上限、YAML の別名の上限）、入力の検査（取り除く項目、注意を出すかどうか、正しい入力は変わらないこと）、ECharts のロケールの選択、乱数の種の固定が元に戻ること。
- **描画テスト**（ヘッドレスの Chrome）: 試作の段階B のケース（20 種類の図、CJK、テーマ、悪意のある入力、外部の画像、誤った入力、大きな入力）を正式なテストにする。各図を単独で描いた結果と、ほかの図に続けて描いた結果が一致すること。
- **テスト用のページの CSP**: Joplin 3.7.24 の CSP と同じにする（4.1節）。外部への要求はルートの記録（`context.route`）で検出する。入力の検査を外すと外部の画像の要求が記録されることを確かめる（検査そのものを試すテスト）。
- **エンジンの再現性のテスト**: `vendor/` の開発版から、記録した手順で `echarts.mjs` を作り直し、SHA-256 が一致すること（15.1節）。
- **手動テスト**: 基準プラグインの M-01〜M-16 を使う。M-11（図の中のリンク）は、リンクを扱わないので除く。
